CLAUDE <-> OLLAMA CONTINUITY FOR WINDOWS
=========================================

GOAL
----
Keep working in the SAME terminal when Claude Code hits a supported usage/provider limit.
When Claude becomes available again, return to Claude automatically at a safe idle boundary.

INSTALL ONCE
------------
1. Install Claude Code, Ollama, Git, and Python 3.
2. Double-click INSTALL_WINDOWS.bat
3. Double-click PULL_MODEL_WINDOWS.bat
4. Double-click CHECK_WINDOWS.bat

NORMAL USE
----------
IMPORTANT: start your coding session with:

START_SMART_CLAUDE_WINDOWS.bat

or from PowerShell:

& "$env:LOCALAPPDATA\claude-ollama-continuity\bin\smart-claude.cmd"

WHAT HAPPENS
------------
Claude Code works normally in the current terminal.

If Claude Code emits StopFailure for one of these conditions:
- rate_limit
- overloaded
- billing_error
- server_error
- max_output_tokens

the supervisor switches that SAME terminal to Claude Code using the local Ollama endpoint and resumes the same Claude session ID.

While Ollama is active, the supervisor periodically performs a tiny real Claude availability probe. When Claude works again, it waits until the Ollama-backed Claude Code session reaches a Stop/idle boundary, then returns to Claude in the SAME terminal using the same session ID.

DEFAULT FALLBACK MODEL
----------------------
qwen3.5

CHANGE MODEL
------------
PowerShell example:
setx CLAUDE_OLLAMA_MODEL qwen3.5

CHECK INTERVAL
--------------
Default: 5 minutes.
To change it, for example to 2 minutes:
setx CLAUDE_CONTINUITY_PROBE_SECONDS 120

SECURITY
--------
Default fallback permission mode: acceptEdits.
FULL_AUTO_ON_WINDOWS.bat enables bypassPermissions and is intentionally NOT the default.

LIMITATION
----------
This depends on Claude Code exposing the provider/usage failure as StopFailure. A context-window compaction event is different and may not trigger provider takeover.
